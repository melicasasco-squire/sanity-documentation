Squire CMS — Reusable Components

Internal documentation for the content team. All blocks available in the Sanity Studio Page Builder.

How Sanity Studio looks

How to navigate

1

Go to studio.sanity.io → Content → choose a document type (Pages, Blog Posts, etc.)

2

Open or create a document. Scroll down to find the Components section — that's the page builder.

3

Click Add item to insert a new block from the component grid.

Best practices

  • Fields marked required must be filled in before publishing.
  • Uppercase styling is handled by CSS — type normally.
  • For links, choose Internal for site pages or URL for external links.
  • Images support hotspot — drag the focal point to control cropping.
  • Changes go live immediately on publish.

Rich Text (Portable Text)

Several components use rich text fields. Use the toolbar to:

  • Normal — regular paragraph (eyebrow, subtitle)
  • H1 / H2 — heading hierarchy
  • Bold — inline emphasis
  • Link — embedded hyperlink on selected text

Block order

Components render in the order they appear in the list. Drag the ⠿ handle on the left of each block to reorder.


To remove a block, expand it and use the ⋯ → Remove menu. This can't be undone without republishing.

Tip: In the page builder grid view, you can search for a component by name. You can also switch to list view if you prefer.

Working in Draft

Every document in Sanity has two states: Published (live on the site) and Draft (your in-progress version). When you open a published document you are viewing the live version — you cannot edit it directly. As soon as you make any change, Sanity automatically creates a Draft copy and shows a Draft badge at the top of the editor.

Draft

While in Draft

All your changes are auto-saved in real time. Nothing is visible on the live site — the draft exists only inside Sanity until you decide to publish it. You can freely edit, review, and iterate without any risk.

Publish

Going live

When your changes are ready, click the Publish button at the top right. The draft replaces the published version immediately. There is no staging preview — once published, it is live.

Discard

Throwing away changes

If you want to go back to the published version without saving your edits, use Discard changes from the document menu (⋯). This permanently deletes the draft — it cannot be undone.

Unpublish

Taking a page offline

Use Unpublish from the document menu to remove the page from the live site. The content is kept as a draft so you can re-publish it later.

⚠ Changes you make in Draft do not go live until you explicitly press Publish. Auto-save only saves the draft — it never publishes automatically.

Translations

The Translations button at the top of any document lets you manage language versions. Squire's site supports multiple locales — each language is a separate, linked document so editing one never affects another. Click the button to see all available translations for the current document, switch to a different language version, or create a new one from scratch. When creating a new translation, the fields start empty — content is not automatically copied or machine-translated.

Page Builder

The Page Builder is the section at the bottom of every Page document where you assemble the visual layout. It works as an ordered list of blocks — each block is one of the components documented in this library (listed in the left sidebar). Click Add item to open the component picker and choose a block type. Once added, expand the block to fill in its fields. You can reorder blocks by dragging the ⠿ handle, and remove them via the ⋯ → Remove menu. The page renders the blocks from top to bottom exactly as they appear in this list.

Document Fields

Before reaching the Page Builder, every document has a set of core fields at the top. Not all document types have all of these — here are the most common ones.

Required

Title

The internal name of the document as it appears in the Sanity Studio list. It is also used as the default page <title> if no SEO Title is set.

Required

Slug

The URL path for this page (e.g. /about-us). Click Generate to auto-fill from the Title, then adjust if needed. Changing a slug after publish will break existing links — avoid unless necessary.

Blog / News

Published At

The publication date shown on the article. It controls sort order in grids and feeds. You can set a future date to schedule visibility — the article must still be Published in Sanity for it to appear.

Pages

Parent Page

Lets you nest a page under another in the URL hierarchy (e.g. setting About as parent of Team gives /about/team). Only available on certain page types.

SEO Fields

Every document type — Pages, Blog Posts, News, etc. — includes an SEO section at the bottom of the editor. These fields control how the page appears in search engines and when shared on social media. They have no effect on the visual layout.

ℹ None of these fields are visible to visitors on the page itself — they only affect search engines, browser tabs, and social media link previews.
Search

SEO Title

The <title> shown in browser tabs and Google results. Aim for 50–60 characters. Falls back to the document Title if left empty.

Search

SEO Description

The snippet shown below the title in search results. Aim for 150–160 characters. Does not affect ranking directly, but a good description improves click-through rate.

Social

OG Image

The image displayed when the page is shared on LinkedIn, Twitter/X, iMessage, etc. Recommended size: 1200 × 630 px. Falls back to a site-wide default if not set.

Crawling

Canonical URL

Tells search engines which URL is the authoritative version of this page. Use when the same content is accessible at multiple URLs to avoid duplicate content penalties. Leave empty if this page has a unique URL.

Crawling

No Index

When checked, adds a noindex tag that tells search engines to exclude this page from results entirely. Use for internal, staging, or duplicate pages.

Crawling

No Follow

When checked, adds a nofollow tag that tells search engines not to follow any links on this page. This prevents passing SEO authority to linked pages. Rarely needed — use with care.

Rich Results

JSON-LD Structured Data

A raw JSON-LD block injected into the page <head>. It provides structured metadata (e.g. Article, BreadcrumbList, FAQPage) that enables rich results in Google Search — star ratings, FAQs, event details, etc. Only fill this in if you know what you are doing or are following a specific schema.
